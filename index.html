Academic Assessment: Limitations of Rule-Based RFM

1. Heuristic & Arbitrary Thresholds: Quantile cuts (e.g., R ≥ 4 vs R < 3) are business assumptions that do not adjust to natural mathematical clusters.
2. High Boundary Sensitivity: A customer on the 79th percentile boundary may fall into an entirely different segment than one on the 81st percentile despite virtually identical behaviors.
3. Equal Weighting Bias: Frequency and Monetary scores are assumed to carry equal weight, whereas in capital-intensive or luxury transactions, Monetary dominates engagement frequency.

Divergent Behavioral Clusters

Cluster 0 Synthesis: K-Means merges 29 At-Risk and 29 Loyal customers into Cluster 0.

Why? In Euclidean space, both groups share very high total monetary spend and high frequency. K-Means prioritizes geometric proximity of spend/frequency over recency decay, whereas RFM explicitly separates them by recency.

Key Academic Takeaway

No Model is "Objectively Correct": Unsupervised clusters lack intrinsic human meaning until annotated.

Recommendation: Use Rule-Based RFM for direct marketing workflows (transparent customer messaging), and use K-Means to discover latent sub-patterns and validate segment cohesion.

Complete SQL code to create database, foreign keys, and indexes
-- Relational Database Schema (MySQL)
CREATE DATABASE IF NOT EXISTS customer_segmentation_db;
USE customer_segmentation_db;

CREATE TABLE customers (
    customer_id INT NOT NULL,
    customer_code VARCHAR(50) NOT NULL,
    signup_date DATE NULL,
    PRIMARY KEY (customer_id),
    UNIQUE KEY uq_customer_code (customer_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE orders (
    order_id INT NOT NULL,
    customer_id INT NOT NULL,
    order_date DATETIME NOT NULL,
    order_status VARCHAR(50) NOT NULL,
    PRIMARY KEY (order_id),
    CONSTRAINT fk_orders_customer FOREIGN KEY (customer_id) 
        REFERENCES customers (customer_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE order_items (
    item_id INT AUTO_INCREMENT NOT NULL,
    order_id INT NOT NULL,
    product_identifier VARCHAR(100) NOT NULL,
    quantity INT NOT NULL,
    unit_price DECIMAL(10, 2) NOT NULL,
    PRIMARY KEY (item_id),
    CONSTRAINT fk_order_items_order FOREIGN KEY (order_id) 
        REFERENCES orders (order_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE segment_runs (
    run_id INT AUTO_INCREMENT NOT NULL,
    method VARCHAR(50) NOT NULL,
    run_date DATETIME NOT NULL,
    parameters TEXT NULL,
    PRIMARY KEY (run_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE customer_segments (
    run_id INT NOT NULL,
    customer_id INT NOT NULL,
    segment_label VARCHAR(100) NOT NULL,
    PRIMARY KEY (run_id, customer_id),
    CONSTRAINT fk_cust_seg_run FOREIGN KEY (run_id) REFERENCES segment_runs (run_id) ON DELETE CASCADE,
    CONSTRAINT fk_cust_seg_customer FOREIGN KEY (customer_id) REFERENCES customers (customer_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
